## Implementation roadmap requirements

Build a dependency-aware roadmap that is implementable by later agents without architecture invention. Prefer vertical/useful slices and foundational infrastructure only where prerequisites demand it. For each implementation stage/slice state:

- goal and user/operator value;
- exact architecture inputs/ADRs;
- modules/processes/data/contracts affected;
- migrations/resources/configuration that implementation may later need;
- provider/account reuse expectation and least-privilege resource boundary;
- whether work is local/fake-first, requires owner dashboard action, or may incur spend;
- tests/benchmark/release evidence required;
- rollback/recovery boundary;
- explicit dependencies and safe parallel work;
- cost/complexity guardrail.

The roadmap must **not** recommend a new provider merely because implementation could be easier. It must preserve the selected Python/TypeScript simplicity and existing Coolify/GitHub/provider-account ecosystem.

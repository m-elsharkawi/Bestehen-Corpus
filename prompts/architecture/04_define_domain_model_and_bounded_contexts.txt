## Project context

Corpus is the A2/B1 German exam-data/intelligence product behind Bestehen / App. It is a one-owner personal project. The App consumes versioned pattern intelligence and owns learner state/Readiness/original practice. The architecture must preserve six independent axes: provenance; authenticity/confidence; rights; difficulty/relevance; capability-specific QA readiness; and identity/derivative lineage/metric-specific independence. Unknown/local/provisional states are first-class, capability publication is scoped, all source/model input is untrusted, and normal App usage is learner-data-free and precomputed rather than live Corpus inference.

## Decisions not to reopen

The six axes are product truth, not optional bounded contexts to merge for convenience. Observed source expression, curated interpretation/correction and derived intelligence remain distinct. Manual overrides survive reruns. Dedup must preserve observations. No domain object may own learner mastery/readiness. No domain-level `ready` boolean may replace capability eligibility.

## Decisions this stage owns

1. **Bounded contexts/modules.** Define clear ownership for Source Acquisition; Provenance/Evidence; Rights/Governance; Canonical Content; Taxonomy/Relevance; Processing; Quality/Findings; Identity/Independence; Analytics; Publication/Contracts; Operations/Audit; Benchmark/Qualification; and Cost/Automation. Merge only where ownership stays unambiguous and personal-project simplicity improves.
2. **Ubiquitous language.** Define precise meanings for Source Family, Source Observation, Document, Exam, Section, Part, Task, Item, Instruction, Stimulus, Response Option, Answer/Scoring, Asset, Evidence, Finding, Decision, Derivation, Revision, Capability Eligibility, Cluster, Independence and Publication.
3. **Ownership matrix.** State which context may create/change each authoritative concept and which contexts consume immutable IDs/references/projections.
4. **Aggregate/value-object/policy boundaries.** Identify transactionally coherent concepts without forcing a physical database schema.
5. **Anti-corruption rules.** Prevent model candidates from becoming curated truth automatically; prevent rights from changing confidence; prevent dedup from deleting observations; prevent QA from rewriting provenance; prevent analytics from becoming source truth.
6. **Stable identity/revision ownership.** Decide which domain concern issues stable IDs and how mutable revisions/versioned interpretations relate without designing storage keys yet.
7. **Uncertainty/state composition.** Define how unknown/disputed/provisional/stale/held/superseded states cross context boundaries and how local child findings influence parent views without invalidating unrelated siblings.
8. **Cross-context communication shape.** Define conceptual commands/events/queries or application-service boundaries only enough to show ownership and dependency direction; Stage 11/19 own physical jobs/contracts.
9. **Audit ownership.** Identify which consequential domain changes require append-only decision/audit entries and which context owns the authoritative record.

## Alternatives

Compare a single undifferentiated domain model with a modular bounded-context model and, if useful, a service-per-context extreme. Recommend the minimum separation that prevents semantic corruption without creating operational service sprawl.

## Cross-cutting requirements

- **Failure/recovery:** ownership must make it possible to keep known-good sibling/capability state when one local context operation fails.
- **Security/rights/privacy:** identify internal trust-sensitive boundaries and prohibited writes; source/model text never gains domain authority.
- **Cost:** boundaries must be coarse enough for one owner; name future split triggers rather than assuming distributed services.
- **Testing:** define domain invariants/property/state-machine tests Stage 25 must later implement.
- **App:** Publication/Contracts may consume Corpus intelligence but must not own learner state or accept learner profiles.

# Agent Prompt — Bestehen / Corpus Architecture — Stage 04 of 28
## Define the Domain Model and Bounded Contexts

You are the domain/data architect responsible for **Stage 04: Domain Model and Bounded Contexts** of Bestehen / Corpus.

This stage establishes architecture language, ownership boundaries and anti-corruption rules that prevent acquisition, evidence, rights, processing, QA, deduplication, analytics and publication from overwriting one another’s truth. This is **architecture decision work, not production implementation**. Do not create production schemas, ORM entities, services, APIs, provider resources, accounts, keys, deployments or live calls.

## Project context

Corpus is the A2/B1 German exam-data/intelligence product behind Bestehen / App. It is a one-owner personal project. App consumes versioned pattern intelligence and owns learner state/Readiness/original practice. Preserve six independent axes: provenance; authenticity/confidence; rights; difficulty/relevance; capability-specific QA readiness; identity/derivative lineage/metric-specific independence. Unknown/local/provisional states are first-class, capability publication is scoped, all source/model input is untrusted, and normal App usage is learner-data-free/precomputed.

## Decisions not to reopen

The six axes are product truth, not optional contexts to merge for convenience. Observed source expression, curated interpretation/correction and derived intelligence remain distinct. Manual overrides survive reruns. Dedup preserves observations. No domain object owns learner mastery/readiness. No domain-level `ready` boolean replaces capability eligibility.

Define bounded contexts/modules for Source Acquisition; Provenance/Evidence; Rights/Governance; Canonical Content; Taxonomy/Relevance; Processing; Quality/Findings; Identity/Independence; Analytics; Publication/Contracts; Operations/Audit; Benchmark/Qualification; Cost/Automation.

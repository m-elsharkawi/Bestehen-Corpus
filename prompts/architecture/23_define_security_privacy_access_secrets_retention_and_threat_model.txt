# Agent Prompt — Bestehen / Corpus Architecture — Stage 23 of 28
## Define Security, Privacy, Access, Secrets, Retention, and Threat Model

You are the security/privacy architect responsible for **Stage 23: Security, Privacy, Access, Secrets, Retention, and Threat Model**.

Consolidate the end-to-end security architecture for untrusted sources, owner access, provider processing, storage, App publication, secrets, retention/deletion and incident response. This is **architecture decision work, not implementation**. Do not configure firewalls/auth/providers, create accounts/apps/keys, rotate secrets, deploy, scan live systems or make provider calls.

## App implementation reuse and no-provisioning rule

Read `Architecture/00-app-implementation-tooling-and-account-reuse-policy.md` and current App implementation provider handoff/runbook plus relevant Pangolin/Auth0/R2/SES/AI/secrets guides. Reuse the existing two-VM Coolify/Pangolin private boundary, Cloudflare/AWS/Auth0/Google/OpenAI account families and protected-ledger conventions where appropriate. Python or TypeScript follows Stage 03. Do not add a secrets SaaS, WAF, IAM product, VPN, security scanner SaaS or new identity provider merely for convenience. New vendor/account requires measured security need, incremental cost/ops, ADR and exit. Do not provision anything.

## Product/security invariants

Corpus holds near-zero personal data and no learner data. External source/model content is untrusted. Rights/security holds may stop use but do not rewrite confidence/trust. Owner actions are audited. Source preview is inert. Secrets never enter source/model payloads, logs or Git. Public submissions/multi-user/private authenticated crawling remain out of launch scope.

## Decisions this stage owns

1. Produce threat model/data-flow diagram across source web, owner browser, Pangolin/private ingress, Corpus app/workers, PostgreSQL, R2, external processors, backups and App publication.
2. Define identity/access: select/reconcile Pangolin-only versus Pangolin + reused Auth0 EU app/client from Stage 20; least privilege, session/re-auth, break-glass and owner-only authorization.
3. Define service identities/credentials between Corpus components and separate App/Corpus data access; same account never means shared broad credential.
4. Define secrets custody, environment injection, rotation/revocation, recovery and no-secret evidence patterns using existing owner conventions.
5. Consolidate SSRF/file/archive/parser/model prompt-injection and egress controls from Stage 12; define residual risks.
6. Define storage encryption/access and explicit separation for Corpus R2 source bytes, backups, temporary processor payloads and App media.
7. Define provider data-minimization/retention/training/subprocessor/region review gates for Gemini/OpenAI/Auth0/SES/R2 as actually used by Corpus; do not claim legal compliance or EU processing without evidence.
8. Define data classification and retention for source observations, reference/prohibited bytes, derived artifacts, model payloads/results, logs/audit, benchmark data, incidental personal data and backups.
9. Define deletion/takedown proof and restore-replay behavior so restored backups do not resurrect suppressed/deleted material.
10. Define audit immutability/access and redaction; logs must not contain raw source payloads by default, secrets or unnecessary personal data.
11. Define supply-chain/model/native-binary security for Python/Node/container/base images/system packages/model artifacts.
12. Define incident states and response for credential exposure, unsafe source, rights complaint, provider data incident, malicious source, compromised dependency and unauthorized owner-console access.
13. Define future triggers before public submissions, multiple operators, external API, private crawling or commercial reuse reopen the threat model.

## Alternatives / cost

Compare reuse of existing private Pangolin/Coolify + account controls with adding public auth/WAF/security SaaS. Prefer private/minimal controls when they satisfy requirements. Include **App implementation reuse assessment**, owner security-maintenance cost and explicit exceptions.

## Failure/testing

Define negative tests for authz, stale sessions, SSRF, archive attacks, prompt injection, secret redaction, cross-product DB/R2 denial, old credential revocation, deletion restore replay and incident circuit behavior. No security control should silently turn a technical failure into content truth.
